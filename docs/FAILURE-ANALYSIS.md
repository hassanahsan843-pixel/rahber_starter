# RAHBAR Failure Analysis: Deliberate Fault Injection

As demonstrated in the RAG lecture: *only Stage F is the model's fault — always diagnose Stages A through E first*. To validate the observability, metrics, and guardrails of RAHBAR, we systematically broke four stages of the pipeline one at a time, recorded the resulting symptoms, detailed the diagnosis process, and verified the remedy.

---

## 1. Stage A: Extraction Failure (Scanned PDF Without OCR)

### How It Was Broken
We modified `indexer/pipeline/extract.py` to disable the `pytesseract` fallback path on the scanned document `Faculty Entrepreneurship and Technical Start-ups Policy` (`27.pdf?20220530`), forcing it to return raw text only.

### Symptom
When asking: *"What percentage of equity must faculty share with the university when launching an on-campus technical start-up?"*, the API returned an honest abstention (`answered_from_context: false`) with: *"The university documents in the corpus do not contain information to answer this question."*

### Diagnosis Without Prior Knowledge
- In `/metrics`, `abstention_count` increased by 1.
- In API structured stdout logs, retrieval logged:
  ```json
  {"logger": "rahbar.answer", "top_k": 5, "scores": [0.24, 0.18, 0.15], "max_score": 0.24, "relevance_floor": 0.55}
  ```
  The query fell below the relevance floor because the vector index contained no meaningful text for that document.
- Inspecting ChromaDB via `collection.get(where={"source": "faculty-entrepreneurship-policy.pdf"})` revealed that chunk text was completely blank (`""`).
- Running `pdffonts corpus/raw/faculty-entrepreneurship-policy.pdf` revealed 0 font objects, confirming that the PDF was an un-indexed bitmap scan.

### Remedy
Reinstate the OCR check in `extract.py`: if `len(text.strip()) < 30`, invoke `pytesseract.image_to_string()`. After re-indexing, the equity sharing clauses were extracted, cosine similarity rose to 0.89, and grounded answers were restored.

## 2. Stage B: Chunking Failure (Fixed 100-Token Chunks With No Overlap)

### How It Was Broken
We modified `indexer/pipeline/chunk.py` to disable structure-aware section splitting and overlap, enforcing fixed-size 100-token windows with 0 tokens overlap (`chunk_size = 100`, `chunk_overlap = 0`).

### Symptom
Evaluation showed that `recall@5` dropped drastically from 0.9231 to 0.6920. Specifically, questions regarding the Generative AI policy and multi-clause prerequisite repeats either failed to retrieve the complete rule or cited severed fragments.

### Diagnosis Without Prior Knowledge
- `eval/run_eval.py` failed the CI gate with the regression message:
  ```text
  GATE FAILED: recall@5 dropped by 0.231 below baseline (max allowed drop is 0.05)
  ```
- Analyzing the golden set breakdown in `eval/results.json` showed that `by_type["ordinary"]` fell to 0.6250.
- Examining the retrieved passages in the API logs showed that section headings were truncated mid-sentence (e.g., `section: "Policy regarding..."` without the subsection number).

### Remedy
Revert to structure-aware recursive splitting with a 400-word target size and 50-word overlap buffer (`chunk_size = 400`, `chunk_overlap = 50`), preserving the active parent heading and ensuring overlap across adjacent chunks.

## 3. Stage C: Retrieval & Embedding Pin Mismatch (Changed EMBED_MODEL on API Only)

### How It Was Broken
The corpus was indexed with `EMBED_MODEL = "nomic-embed-text"`. We then updated the API's environment variable to `EMBED_MODEL = "all-minilm-l6-v2"` without re-indexing Chroma.

### Symptom
Without our guardrail, the system would silently fail: dense query vectors generated by MiniLM would be compared against Nomic vectors in Chroma, returning completely unrelated chunks with low scores or garbage retrievals.
With our code guardrail, the API container refused to become ready:
```text
$ kubectl get pods -n rahbar
NAME                        READY   STATUS    RESTARTS   AGE
rahbar-api-6878b665-x7j4    0/1     Running   0          42s
```

### Diagnosis Without Prior Knowledge
- `kubectl describe pod rahbar-api-...` showed `Readiness probe failed: HTTP probe failed with statuscode: 503`.
- `kubectl logs rahbar-api-...` printed the exact guardrail conflict:
  ```json
  {"logger": "rahbar.health", "msg": "embed_model mismatch: collection uses 'nomic-embed-text' but EMBED_MODEL is 'all-minilm-l6-v2'"}
  ```

### Remedy
Align `EMBED_MODEL` in the ConfigMap across both the indexer and API deployments (`EMBED_MODEL: "nomic-embed-text"`), or execute a full re-indexing Job if changing embedding models.

## 4. Stage E: Source Failure (Removed Superseded Filter on Policy Versions)

### How It Was Broken
In `api/app/retrieval/chroma.py`, we removed the metadata filter `where={"superseded": {"$eq": False}}` and queried Chroma with an unfiltered query for prerequisite rules.

### Symptom
When asking: *"Can I conditionally register for a course after failing its prerequisite?"*, the retriever retrieved clause 4.2 from the superseded 2023 Undergraduate Academic Rules instead of the authoritative 2026 Academic Rules Handbook. The API confidently generated an obsolete answer quoting repealed regulations.

### Diagnosis Without Prior Knowledge
- While the response looked fluent and confident (`confidence: "high"`), the version check in `eval/run_eval.py` failed:
  ```text
  Question q09: Expected 'academic-rules-handbook-jun-2026.pdf', but retrieved 'undergraduate-academic-rules-aug-2023.pdf'
  ```
- In the API logs, `chunk_ids` revealed that the top-ranked hit had `doc_version: "2023-08"` and `superseded: True`.
- Because dense semantic similarity for identical policy topics is nearly identical between 2023 and 2026 versions, vector similarity alone cannot distinguish current policy from repealed policy.

### Remedy
Reinstate strict metadata filtering in `chroma.py`:
```python
include_superseded = "2023" in question or "old" in question.lower()
where_filter = None if include_superseded else {"superseded": {"$eq": False}}
```
This guarantees that repealed documents are excluded from retrieval unless the user explicitly inquires about historical policies.
